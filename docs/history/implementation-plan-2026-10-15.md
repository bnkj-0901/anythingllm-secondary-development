# 知识库首期实施计划

> 历史计划，2026-10-19 由 [源码二次开发计划](../../tasks/plan.md) 替代。下文保留当时范围和进展，不代表当前执行路线。

日期：2026-10-15。用户明确要求：先做知识库，ERP 和 App 后置；优先复用成熟开源源码，完成整合。

## 首期范围

电脑工作台、公共/企业/个人知识空间、文字/图片/语音/文档录入、人工核对、来源版本、检索问答、原文引用、纠错反馈，以及微信小程序和公众号接入。图片识别后必须人工确认，确认前不成为正式知识。

不包含库存、采购销售、经营记账、财税、支付订阅、Android/iOS App、连续实时语音和多品牌批量发布。

## 实施方式

以 AnythingLLM v1.18.0 的源码为底座，固定提交并保留 MIT 许可证和版权声明。复用其已有电脑工作台、多用户模式、文档处理、OCR、音频转写、向量检索、问答引用和供应商适配。

先运行原版并用真实资料验证，再补缺失功能。只有版本发布、人工确认、审计或微信权限等实际缺口需要项目代码；不预先重建账号、数据库、检索引擎和后台页面。后续 ERP 和 App 通过稳定接口接入。

底座 developer API key 只用于服务端。工作空间 slug 不能直接作为客户端声称的授权，微信用户到知识空间的映射必须在服务端验证。现有多用户模式也需通过跨空间、撤权和引用访问测试后才能作为隔离保证。

## 交付顺序与估算

以下是范围收缩后的初步规划，以两名主要开发人员、测试分阶段参与、模型与微信账号及时可用为前提；从实际开工累计，阶段并非相加。完成样本验证后重新估算。

| 累计目标 | 交付内容 | 验证门槛 |
|---|---|---|
| 1–2 周 | 可试用的电脑知识库，文字/文档上传、问答、引用 | 真实资料完整跑通、配置与数据重启不丢失 |
| 3–4 周 | 多用户权限、来源版本与人工确认 | 跨企业/私有知识隔离、未确认不入库、撤回不再被引用 |
| 4–6 周 | 四类录入、微信入口与反馈闭环 | 图片/语音真实效果、小程序真机与公众号回调 |
| 6–8 周 | 试运行、质量修正、备份恢复与上线材料 | 固定题集、权限回归、费用限额与恢复演练 |

该估算不把“原版能运行”等同于业务要求已经全部交付。微信认证/备案/审核、账号准备、行业资料清洗与模型不可用的等待时间另记。复杂 PDF、行业语音或发布一致性需要较大改造时重新评估相关阶段。

## 当前环境与限制

当前主机具备 Python、Node.js 和 Git，未安装 Docker。已通过 Windows 本地源码运行：两项服务、账号与模型配置、自助注册、H5、个人后台、公共／私有知识库、文字/TXT 入库、阿里向量索引、DeepSeek 引用问答与跨用户权限。当前不再以 Docker 作为本地试用前提；Docker 构建、多模态样本、完整业务评测和公网部署仍需后续验收。微信暂时没有平台资质，已提供授权接入与配置入口，真实回调未联调。

当前记录见 [开源整合说明](../docs/open-source-integration.md) 和 [任务清单](todo.md)。原完整技术方案保留需求与验收参考，其中“从零自研 FastAPI + Worker + React 后台”的实现路线已被 ADR-002 调整。
