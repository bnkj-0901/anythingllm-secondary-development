# AnythingLLM 源码二次开发规格

日期：2026-10-19。状态：本轮重新梳理的目标规格，功能尚未按此方案迁移。

依据：用户明确选择“不要运行时补丁，不做上层服务，直接二次开发”。本文与 [ADR-003](../decisions/knowledge-platform-003.md) 取代此前适配层实施路线；实施顺序见 [计划](../../tasks/plan.md) 和 [任务](../../tasks/todo.md)。

## 1. 目标与范围

交付一个基于 AnythingLLM 源码的多用户知识库应用。用户在电脑和手机 H5 使用同一套账号、个人后台、资料和问答。共享/私有是内容权限，不引入租户、企业组织、订阅、计费或 SaaS 管理模型。

已确认的业务规则：

- 用户可上传文字、文档和图片，选择共享库或本人私有库。
- 私有资料在完成必要的文字核对、成功索引后供本人查询，不需要共享审核。
- 共享投稿必须经过平台管理员审核；审核通过且索引成功后，其他用户才可检索。
- 用户问答默认同时检索已发布共享知识和本人私有知识，生成一个有来源的回答。
- 图片识别先产生可编辑草稿，上传者核对文字；选择共享投稿时仍须管理员审核。这是两个独立步骤。
- 保留自助注册、用户管理、微信 H5 登录接入及配置、阿里百炼图片识别配置；微信真实登录仍依赖账号资质与 HTTPS 回调域名。
- ERP、库存记账、Android/iOS App 后置。独立小程序、公众号消息机器人、实时语音不作为本轮闭环的依赖；语音录入放在核心流程稳定后复用上游转写能力。

本方案采用的实施默认值：共享范围为所有已登录用户，匿名访问关闭；初期一个默认共享库；每个用户有默认私有库，已有多个所属私有库继续保留，统一问答检索本人全部有效私有库。管理员可管理私有资料，但日常问答默认仍使用“共享＋管理员本人私有”，不自动查询其他用户私有内容。经理角色保留账号兼容，新增业务权限按普通用户处理。

## 2. 原版能力与当前差距

基线：AnythingLLM v1.18.0，提交 `3e4f9411b67f2dd7fa9fc6f2b95dfacbda0633ba`，MIT。

| 能力 | 源码核对结果 | 处理 |
|---|---|---|
| 用户、密码、多用户登录、管理页 | 已有 | 复用并补自助注册与微信身份 |
| 工作空间及成员分配 | 已有；原版 admin/manager 可访问全部空间 | 扩展共享/所属字段，统一授权 |
| 解析、切分、embedding、向量适配、问答引用 | 已有 | 复用，不重写通用引擎 |
| 普通用户持久入库 | 原版核心入库接口限制 admin/manager | 正式加入“本人私有上传／共享投稿”入口 |
| 共享投稿审核 | 没有本需求对应的流程 | 新增版本、审核记录和发布状态 |
| 多库联合问答 | 原版标准问答使用当前 workspace 的 namespace | 修改检索调用链，共用授权后的联合检索模块 |
| 个人聊天附件 | 有，按用户及当前空间/会话读取全文上下文 | 保留附件用途，不当作个人向量库 |

当前本地还在运行旧适配方式：`local-runtime.cjs` 预加载；`access/runtime.cjs` 动态挂载路由、替换函数并注入脚本；业务资料映射和图片草稿使用 `system_settings` 的 `kb_access_*` 行。现有共享库由管理员维护，没有普通用户共享投稿审核，问答没有自动联合检索。历史验证记录仅证明旧实现当时的能力。

## 3. 工程架构

一个产品、一套身份与业务数据，沿用 AnythingLLM 原有组件：

```text
AnythingLLM 项目源码（当前路径 vendor/anythingllm）
├─ frontend/src/              React 工作台、个人后台、H5、审核与配置页面
├─ server/endpoints/          正式注册的身份、知识、审核、问答路由
├─ server/models/             Prisma 模型访问与事务
├─ server/utils/knowledge/    权限、投稿发布、联合检索等内部模块（新增）
├─ server/jobs/               可重试的索引及清理任务
├─ server/prisma/             原有 schema + 增量迁移
└─ collector/                 原有解析服务，复用并直接修改必要代码
```

前端直接请求本项目 server。知识业务模块是同一 server 内的普通源码模块，不再通过一层服务转调本机 developer API。Collector 仍是 AnythingLLM 原有的解析组件，可保留独立进程；这不新增一套业务后台。

所有新路由在 `server/index.js` 正式注册，页面在 `frontend/src/main.jsx` 正式声明。权限和问答通过显式函数调用，Windows 监听地址、Collector 地址和路径兼容在对应源码中修正。目标运行不使用 `--require local-runtime.cjs`、原型替换、require 劫持、函数覆盖、HTML/DOM 脚本注入。

源码治理：保留 MIT 及上游来源。`main` 的首个提交保存与上游完全一致的源码树；`feature/knowledge-platform` 的第二个提交保留当前目录布局、现有扩展和本文档，源码作为 `vendor/anythingllm/` 下的实际文件跟踪，不再忽略或仅提交一个嵌套仓库指针。`fetch-source.ps1` 兼容从项目仓库克隆的源码；旧本地嵌套检出仍校验原版版本。后续开发在项目分支继续，启动切换与数据迁移仍待实施。

## 4. 权限与页面

| 操作 | 普通用户/经理 | 平台管理员 |
|---|---|---|
| 上传、修改、删除本人私有资料 | 允许 | 可管理，记录操作人 |
| 查询他人私有资料 | 禁止 | 仅在明确的管理范围操作，不纳入默认问答 |
| 共享投稿、查看本人审核结果 | 允许 | 允许 |
| 查看他人的未发布投稿及原图 | 禁止 | 允许审核 |
| 审核、驳回、撤回共享发布 | 禁止 | 允许，留下记录 |
| 检索已发布共享资料 | 允许 | 允许 |
| 模型/微信/识别配置、全局用户和文件管理 | 禁止 | 允许 |

个人后台包括“问答、我的私有资料、共享资料、我的投稿、图片核对”；管理员增加“待审核、发布管理、用户、系统配置”。资料上传处选择“私有保存／提交共享审核”，不以赋予 manager 权限换取上传能力。

保留 `/portal`、`/register`、`/h5`、`/access/admin` 的入口语义，改成正式 React 路由；`/portal?space=…&image=…` 保留图片草稿定位能力。登录复用原版认证链，在源码内整合现有 H5 与微信流程，逐步消除为桥接两套页面而建立的重复会话。禁用账号对所有请求生效；聊天、线程与历史始终按用户隔离。

## 5. 数据设计

首期沿用现有 SQLite + Prisma 和已配置的向量引擎，不在这次重构同时更换数据库。用户、聊天、工作空间、模型配置继续复用原表；原图/文件保存在非公开存储，关系数据库保存授权、版本及文件定位，向量库保存检索副本。

以下是待实施的逻辑模型，实际字段与外键通过增量 Prisma migration 落地：

| 表/扩展 | 关键字段与职责 |
|---|---|
| `users`（复用） | 账号、密码哈希、角色、禁用状态；不建立第二套业务用户 |
| `workspaces`（扩展） | `knowledgeType: LEGACY/SHARED/PRIVATE`、`ownerId`；PRIVATE 必须有关联用户，SHARED 不归某个普通用户；默认 LEGACY 防止旧空间自动公开 |
| `knowledge_documents`（新增） | 稳定资料 ID、目标 workspace、提交用户、标题、`activeVersionId`、撤回/删除状态；同一资料包含多个版本 |
| `knowledge_versions`（新增） | `documentId`、递增版本号、最终正文/存储定位、内容哈希、原件引用、识别引擎、核对人/时间、独立的审核状态和索引状态 |
| `knowledge_assets`（新增） | 上传用户、受控原件路径、真实类型、大小、SHA256；关联版本；原件访问重新鉴权 |
| `knowledge_review_events`（新增） | 版本、提交/通过/驳回/撤回事件、操作人、原因、时间；审核决定绑定不可变版本及内容哈希 |
| `knowledge_index_jobs`（新增） | 版本、目标命名空间、操作、状态、重试次数/租约、错误摘要、唯一幂等键；发布事务内登记任务 |
| `workspace_documents`（扩展复用） | 关联 `knowledgeVersionId`，允许一个版本对应多个解析文档；映射原有 Document 与向量 ID |
| `user_external_identities`（新增） | 微信 provider、AppID、OpenID、用户 FK；应用+OpenID 唯一；不按昵称合并 |
| `oauth_states`（新增） | state 哈希、浏览器绑定、provider、过期时间、单次消费状态；旧临时 state 不迁移 |
| `system_settings`（保留配置用途） | 注册开关、默认共享库 ID、加密的微信/视觉服务配置；不继续存业务资料、所属关系、审核及任务大 JSON |

约束：`(documentId, version)` 唯一；发布必须指向该资料自身的可发布版本；任务幂等键唯一；`ownerId`、提交用户、审核人、目标空间和版本引用有外键/索引。SQLite 中状态使用字符串并在模型校验合法值及迁移中落实可行约束，不假设原生 Prisma enum 支持。来源引用固定到版本与原件，而非仅指向可覆盖标题。

## 6. 投稿、审核与发布

```text
上传 → 解析/识别 → 可编辑草稿 → 用户核对并提交不可变版本
                              ├─ 私有：NOT_REQUIRED → 索引 → 激活 → 本人可检索
                              └─ 共享：PENDING → 管理员审核
                                                ├─ REJECTED → 查看原因/新版本重提
                                                └─ APPROVED → 索引 → 激活 → 全体登录用户可检索
```

审核状态与索引状态分别保存：`NOT_REQUIRED/PENDING/APPROVED/REJECTED` 与 `NOT_INDEXED/QUEUED/INDEXING/READY/FAILED`。`APPROVED` 不等于已发布；资料有可用 `activeVersionId` 且未撤回，才属于可检索知识。

提交/审核使用版本号或条件更新防并发，重复操作返回原结果。用户编辑已送审内容必须生成新版本，旧审核不能授权新正文；已发布共享内容修订重新送审。新版本尚未发布时旧有效版本继续服务。私有转共享也走投稿，禁止直接改空间标记绕过审核；已发布共享内容由管理员撤回，投稿者不能悄悄覆盖或删除。

数据库与向量引擎没有跨系统事务：数据库事务保存审核结果和索引任务，任务可恢复重试。向量片段携带资料/版本/空间 ID；全部写入成功后，事务检查版本仍获授权，再切换 activeVersionId。查询在送入模型前按数据库当前有效版本过滤，因此部分写入、索引失败、旧任务重放均不能提前暴露新版本。

撤回先在数据库停用该版本，之后异步清理向量；清理失败仍不可检索。重新发布与旧清理任务使用版本身份隔离，防止误删新版。共享库草稿、驳回和索引失败资料及原件仅提交者和管理员可读。历史已发回答、下载和已经输出到客户端的内容无法远程收回。

## 7. 联合检索与防绕过

同一源码内新增统一模块 `server/utils/knowledge/retrieval.js`（计划路径）：

1. 从已验证登录态获取用户，检查未禁用，构建“已发布共享空间＋ownerId 为本人且有效的私有空间”范围；普通客户端不能提交任意用户 ID 或 namespace 授权自己。
2. 在授权空间分别复用向量适配器召回。仅合并同一 embedding 配置/维度的结果；模型切换需重建索引并验证兼容性，不能直接混搜不同向量空间。
3. 批量读取数据库，剔除未激活、撤回、旧版及未授权片段，再做去重、排名融合/可选重排。对过滤不足的召回按上限补取，避免前 K 个全是失效片段而误报无资料。
4. 按统一上下文预算组装相关片段，调用一次聊天模型；引用标注共享/私有、标题、资料版本和受控原文入口。生成前再次检查权限与有效性。没有足够依据时明确说明。

普通流式问答、developer API 同步/流式、OpenAI 兼容入口、向量搜索、agent memory 检索必须使用同一授权模块，或在未接入时对受管理知识明确拒绝访问，不能保留旧单空间旁路。匿名嵌入、API key 调用不自动继承任何用户私有范围；缺少用户身份的入口首期关闭，后续显式授权。

同样检查固定文档、个人附件、聊天历史、自动记忆、原文/原图、全局文件列表和缓存。用户私人附件保持个人会话范围，不自动变为共享知识；自动记忆与 agent 写入不能绕过共享审核，首期禁止向受管理共享命名空间直接写入。新请求不再把已撤回的来源重新加入模型上下文；旧聊天中相关引用内容过滤，无法识别来源的历史不作为可靠资料自动复用。历史已展示内容不因此消失。

## 8. 同一服务内的接口边界

具体端点实现时写入接口合同与测试；以下为目标入口，尚未上线：

| 入口 | 输入与返回 | 授权 |
|---|---|---|
| `POST /api/knowledge/documents` | `{workspaceId,title,sourceType}` → `{documentId,versionId,version,status}` | 校验本人私有或合法共享投稿目标，作者取登录态 |
| `PATCH /api/knowledge/documents/:id/versions/:version` | `{expectedRevision,text}` → 新草稿修订号 | 作者本人可改未提交草稿；冲突 409 |
| `POST /api/knowledge/documents/:id/submissions` | `{version,expectedRevision}` → 审核/索引状态 | 作者本人，图片要求已有核对快照 |
| `GET /api/knowledge/submissions` | `page,pageSize,status` → `{data,pagination}` | 普通用户仅本人；管理审核列表另作权限控制 |
| `POST /api/knowledge/documents/:id/reviews` | `{version,decision,reason}` → `{reviewId,reviewStatus,indexStatus}` | 管理员；驳回必须有原因，批准不能由客户端声称索引完成 |
| `GET /api/knowledge/documents/:id/source` | 版本定位 → 受控正文/原件 | 按当前发布/所属/投稿权限重查 |
| `POST /api/knowledge/query` | `{message,threadId?}` → 沿用原版流式事件及引用 | 登录用户，线程需属本人，服务器决定检索范围 |

文件上传、图片识别/核对沿用现有行为并迁成正式源码接口。分页上限与上传限额由服务端控制。新知识接口错误统一为 `{error:{code,message}}`；401 未登录，404 资源不存在或不可见，403 无操作权，409 版本冲突，422 输入无效，429 限流，503 依赖不可用。内部错误不回传密钥和路径。旧 `/api/access/*` 如需过渡，以同一 server 中显式兼容路由转同一实现，迁移完成后统一清理。

## 9. 迁移与切换

先在备份副本演练，再对运行数据执行迁移。备份覆盖 SQLite 一致性快照、整个 storage（原件/草稿/向量）、配置及原 SIG_KEY/SIG_SALT；禁止重新生成密钥导致旧配置无法解密。

- 保留现有 users/workspaces/聊天 ID、密码哈希、模型与向量配置。
- 将 `kb_access_space_*` 转为正式共享/私有所属字段，无法判定的空间保留 LEGACY，不自动公开、不分配给猜测的用户。
- 已有私有索引映射为迁移版本；已有共享资料先由管理员确认历史发布清单再激活。新规则下新投稿绝不自动批准。
- 图片草稿、最终文字、识别引擎/进度、确认快照、原图哈希与文件映射到新表；保留旧 ID 或明确转换映射，旧核对链接可定位。中断任务记录可恢复失败。
- 微信身份映射转正式表；加密配置保留可解密性。旧短期 OAuth state 作废后重新发起登录。
- 迁移逐项校验数量、哈希、外键、所属人与可见性，幂等可重复，产出不含秘密的核对报告。
- 演练中证明原生路由/UI可用后再切换启动。最终验收目标是无预加载适配器运行；此前页面可用不代表迁移完成。

回退以切换前完整数据和索引快照为单位，避免新版 DB 与旧版向量混用；控制写入窗口，记录切换后新增资料，回退前先保全这些新增内容。旧代码和原始记录在验证完成前保留，不能直接删掉再重建。

## 10. 开发命令、规范与验证

代码沿用 React 18、Express 4、CommonJS server、Prisma 5.3.1、Node 22 和现有锁文件。遵循所在源码的双引号、分号、命名及现有模型调用方式；新增知识模块集中放置，避免把全部业务堆进 `index.js`。

示意（待实现，非当前已存在函数）：

```js
const scope = await KnowledgeAccess.forUser(user);
const result = await KnowledgeRetrieval.search({ scope, message });
```

源码开发时从项目根目录执行；新增测试目录建立后才执行其测试命令：

```powershell
git -C .\vendor\anythingllm diff --check
.\vendor\anythingllm\server\node_modules\.bin\prisma.cmd validate --schema .\vendor\anythingllm\server\prisma\schema.prisma
node --test .\vendor\anythingllm\server\__tests__\knowledge\*.test.cjs

npm --prefix .\vendor\anythingllm\collector run lint:check
npm --prefix .\vendor\anythingllm\frontend run lint:check

```

lint 需要组件的开发依赖。原版既有 Jest 用例与新增 Node 原生测试分开运行，不能声称上述命令覆盖所有原版测试。现有 `start-local.ps1` 与旧扩展测试只用于旧版本基线；新启动方案在移除预加载后单独验证，当前不把旧校验当作新版本验收。

测试聚焦业务结果：A/B 两普通用户＋管理员；A 私有、B 私有、已发布共享、待审共享、驳回、索引失败、撤回各置不同标记。证明 A 的同一问题可引用共享及 A 私有，无法获取 B 私有或任何未发布共享。另测改版重审、并发审核、部分索引、任务重放、崩溃恢复、原件撤权、所有问答旁路、图片更正、重复确认，以及重启后持久化。替身测试不代表真实模型或微信联调通过。

页面以真实浏览器验收桌面/手机尺寸、注册/登录/退出、上传选范围、图片核对、管理员审核、混合来源回答；迁移使用旧数据副本演练并出核对报告。真实模型费用和 OCR 质量单独记录；业务表格不能只靠合成样本验收。

边界：始终保留已有数据与许可证、服务端鉴权、加密密钥和可追溯状态；不自动公开旧资料、不把个人数据交给所有用户、不依赖提示词执行权限或审核；公网部署、真实微信联调、外部仓库发布按相应任务执行，不在这轮文档梳理中发生。

## 11. 完成标准

- 无运行时业务补丁、无上层业务服务，源代码提交可恢复、可构建，原生前端与路由直接提供功能。
- 上传私有与共享的路径真实可用，管理员审核成功与索引完成分别可观测；任何未获发布授权的共享版本不能参与问答。
- 一个问题可同时引用共享和本人私有资料，跨用户反例和所有启用入口的权限回归通过。
- 原账号、资料、图片、模型配置和核对链接完成迁移核验；重启、失败重试与恢复演练通过。
- 微信无资质时如实显示未开通，具备凭据后能开展真实联调；不以配置页存在宣称真实登录通过。
